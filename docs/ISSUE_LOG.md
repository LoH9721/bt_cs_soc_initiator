# 开发问题台账

更新时间：2026-08-19

本文件用于记录开发中途发现、但尚未完成归类的问题。记录问题不代表已经批准修改代码，也不代表必须创建新 CR。

## 1. 使用规则

1. 发现时先分配不可复用的 `I-NNN` 编号，只记录事实、风险和证据。
2. 评审后选择一种归宿：并入现有子项、新增当前 CR 子项、升级为新 CR、关闭或暂缓。
3. 转入 CR 后保留原问题行，并填写目标编号，保证发现过程可追溯。
4. 未经用户确认，不把 `NEW` 或 `TRIAGED` 问题直接转为代码修改。

状态：`NEW / TRIAGED / PROMOTED / RESOLVED / WONT_DO / DEFERRED`。

## 3. 归类判断

- 当前改动引入的回归：在当前子项内修复并补验证。
- 与当前 CR 同主题、同风险闭环：新增当前 CR 子项。
- 独立主题、独立风险或独立验证闭环：需要实施时再建立新 CR。
- 暂不影响阶段目标：保留为 `DEFERRED`，不打断当前子项。
