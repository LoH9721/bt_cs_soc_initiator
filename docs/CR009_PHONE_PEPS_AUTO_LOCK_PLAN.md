# CR009 手机 PEPS 自动解闭锁策略计划

状态：`DRAFT`

更新时间：2026-08-19

## 1. 目标

在 CR008 已建立的授权 Passive L4 链路和新鲜测距基础上，定义手机 PEPS 的产品级自动解锁、离车闭锁、防重复和兜底策略，避免区域抖动、短暂断连或车辆状态变化造成重复或错误命令。

## 2. 当前边界

- CR008 的授权 Bond、L4 门控、测距新鲜度和授权断连快照继续作为安全基础，不在 CR009 中重复实现。
- 当前只有手机钥匙，`APP_KEY_ENABLE=0`；实体钥匙并发策略不是本阶段默认范围。
- 不修改 APP-BG24 命令字、TLV、加密格式、GATT、HID Report Map、Appearance 和串口调试接口。
- 行车速度/挡位触发的自动落锁应优先由 BCM/整车控制器负责；BG24 是否参与必须有明确车辆信号和需求依据。
- 文档中的候选子项不等于批准实施；每个子项仍需单独方案确认、修改、编译和实机验证。

## 3. 当前已知逻辑

- 自动解锁：确认区域由闭锁区/无效区进入解锁区/车内时触发。
- 区域判定：迟滞状态机 + 连续 5 次去抖。
- 自动命令：2 秒冷却；车辆已解锁时跳过；自动解锁消耗额度。
- 首次区域定位不会触发自动解锁。
- 当前没有基于“走远进入闭锁区”的自动闭锁。
- 当前自动闭锁仅来自 CR008-010：授权 Passive L4 链路断开持续 5 秒。

## 4. 候选子项

候选子项和实时状态统一维护在 `CR_STATUS.md`。当前候选范围：

- CR009-001：车辆条件门控（解锁要求当前 LOCKED、闭锁要求当前 UNLOCKED；门/尾门抑制、非静默；不硬性 IGN/门）。
- CR009-002：Approach / Leave Cycle 与目标状态门闩（一次周期只动一次）。
- CR009-003：Phone Auto 命令结果闭环（初版不自动重试）。
- CR009-004：正常离车闭锁请求（可信离车意图）。
- CR009-005：断连闭锁兜底（复用 CR008-010，仅在有离车证据时）。
- CR009-006：自动解锁额度语义（蓝牙自动解锁次数计数，解耦闭锁）。
- CR009-007：多源协调与让行（Phone Auto / 手动 / VIU / PEPS / Key）。
- CR009-008：自动回锁（CANCELLED —— VIU 已实现自动回锁，BG24 不重复）。

- 新发现问题先写入 `ISSUE_LOG.md`，完成归类后再进入 CR009 或新 CR。

## 6. 统一验证原则

- 前后对比记录区域、距离、授权门控、车辆锁状态和自动命令日志。
- 覆盖靠近、驻留、边界往返、走远、短暂断连、持续断连、重连和重启。
- 覆盖车辆已锁/已解锁、IGN OFF/非 OFF、车门开/关和状态未知。
- 验证自动命令只产生一次，并由车辆锁状态反馈确认结果。
- 回归 CR008-009 的未授权/STALE 门控和 CR008-010 的授权断连来源。

## 7. 已确认决策

- 锁状态只用 0x282 `DriverDoorLockSt`，仅 LOCKED/UNLOCKED 两态，保持最后一次值，不引入 UNKNOWN/有效性判定；不采用 `RTE_VIU_FINAL_LOCK_STATE`。
- 不新增 P 挡信号，P 挡由 VIU 裁决。
- 驾驶门“开→关”作为离车上下文的软使能证据，不作为硬门槛；任一监控门/尾门打开必须硬性抑制离车候选。
- 自动闭锁不要求 IGN=OFF；自动解锁不硬性要求 IGN=OFF 或所有门关闭。
- 不采用 `PEPS_KEY_IN_CAR`（未接线死信号，纯手机场景由手机 INSIDE 区覆盖，实体钥匙未启用）。
- 额度：蓝牙自动解锁次数计数，发命令即扣、不返还、不归因，解耦闭锁。
- CR009-008：取消，VIU 已实现自动回锁，BG24 不重复实现。
