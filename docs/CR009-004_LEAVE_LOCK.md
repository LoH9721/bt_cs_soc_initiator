# CR009-004 连接状态走远闭锁（离车闭锁）设计

状态：`CODED`（已提交 `ab9734b`，编译待确认）

更新时间：2026-08-19

## 1. 目标

手机仍保持蓝牙连接、但人已走远时，自动请求一次闭锁。触发点选在"闭锁区 → 无效区"（约 15m），用门资格（解锁状态 + 任一门开到所有门关闭）防止无门动作的往返反复闭锁。断连闭锁（CR009-005）仍作为最后兜底。

## 2. 原有逻辑（引用文件/函数）

- 自动命令检测：`detect_auto_cmd()`（`user_app_fun/user_app_phone_peps.c:260`）只返回 UNLOCK（闭锁区/无效区 → 解锁区/车内），没有任何"连接状态下走远闭锁"路径。
- 自动闭锁仅两条路：断连闭锁（CR008-010 + CR009-001/005）和 Key 侧（`APP_KEY_ENABLE=0`，未启用）。
- 区域阈值：`unlock_exit=1000`、`invalid_enter=1500`（cm）；走远逐跳确认，必须先确认进入闭锁区再进入无效区。

## 3. 必要性

BLE 连接可保持约 30m，只靠断连闭锁会让闭锁推迟到 30m 断连后（再等 5s）。004 让人走过约 15m 就提前请求闭锁；不同手机射频差异导致的断连距离差异不再直接决定闭锁距离。

## 4. 不修改的风险

闭锁距离取决于各手机 BLE 断连距离（10~30m 不等），射频强的手机锁车明显偏晚。

## 5. 修改位置（文件+函数）

1. `config/app_config.h`：新增 `PHONE_PEPS_LEAVE_LOCK_ENABLE`（默认 1），控制整个连接状态走远闭锁（含门资格）。
2. `user_app_fun/user_app_phone_peps.c`：
   - `detect_auto_cmd()`：新增 `OUTSIDE_LOCK → PARKING_INVALID` 返回 `APP_PROTO_REMOTE_CMD_LOCK`（`#if PHONE_PEPS_LEAVE_LOCK_ENABLE` 内）。
   - `user_app_phone_peps_process()`：
     - 门资格建立：授权链路下，`g_prev_door_status != 0U && door_status == 0U && lock_state == UNLOCKED`（任一门开到所有门关闭边沿）→ `g_leave_lock_qualified = true`。
     - 资格撤销：区域确认回到 `OUTSIDE_UNLOCK` 或 `IN_CAR` → 资格清零；无新门动作不恢复。
     - 命令块新增 LOCK 门控：已闭锁 / 静默 / 门/尾门开 / 无资格 → 跳过；发送后资格消耗（本周期只闭锁一次）；发送日志按 UNLOCK/LOCK 区分。
   - `user_app_phone_peps_init()` / `user_app_phone_peps_on_disconnected()` / 非授权分支：复位资格与门状态快照。

## 6. 影响点与冲突检查

- 与 CR008-010：断连闭锁来源不变，004 只是新增"连接状态下"路径；004 已闭锁后 0x282=LOCKED，005 启动条件不成立，不会重复闭锁。
- 与 CR009-001：静默/门控在 004 中同样生效。
- 与 CR009-005：004 是主路径、005 是兜底，互补；宏只控制 004，不影响 005。
- 与 CR009-006：004 不扣额度，额度语义保持不变。
- 与 CR009-009（热保护）：已取消，不参与。
- 冻结接口：不改命令字/TLV/加密/GATT/HID/Appearance/串口调试接口。

## 8. 前后对比实测方法

- 解锁 → 任一门开 → 全关 → 走远 15m → 闭锁一次（改前不产生任何连接状态闭锁）。
- 解锁后没门动作直接走远 → 不区域闭锁，断连后 005 兜底。
- 走远到 10m 折回 8m 内再走远 → 无资格不区域闭锁（防反复）。
- 门/尾门开着走远 → 004 和 005 都不锁（防夹，预期）。
- 已闭锁 / 静默期 → 不锁。
- `PHONE_PEPS_LEAVE_LOCK_ENABLE=0` → 004 完全关闭，005 照常。
- 回归自动解锁、CR008-010、CR009-001/005/006。
