## CR009-006 自动解锁额度语义

- 状态：TESTED（用户确认编译和实机测试通过）
- 原有逻辑：断连自动闭锁（CR008-010）的启动和取消条件额外挂了“自动解锁额度”判断，额度=0 时离车断连 5s 不再自动闭锁。
- 必要性：额度是“自动解锁”额度，不应卡自动闭锁。
- 不修改风险：不改则额度=0 时离车不自动闭锁。
- 实际改动：删除 `user_app_phone_peps.c` 断连闭锁启动条件的 `&& phone_comm_get_passive_quota() > 0U`；删除取消条件的 `phone_comm_get_passive_quota() == 0U ||`。
- 文件与函数：`user_app_fun/user_app_phone_peps.c` 的 `user_app_phone_peps_process()`。
- 影响范围：只影响断连自动闭锁门控；额度扣减逻辑和自动解锁路径不变。
- 与 CR008 和 CR009 其他子项的冲突检查：不改 CR008-010 授权断连事件来源；与 CR009-001 同段代码，已先做本项。
- 编译方法：Simplicity Studio 编译，仅改 `.c`。
- 前后对比实测方法：额度=0 断连 5s 仍闭锁；额度>0 行为不变；自动解锁仍扣额度；回归 CR008-010。
- 实际验证证据：用户确认编译和实机测试通过。

## CR009-001 车辆自动动作门控

- 状态：BUILT（用户确认编译通过，实机待测）
- 原有逻辑：自动解锁只看锁状态（`lock_state == UNLOCKED` 跳过），断连闭锁只看 `lock_state != LOCKED`，均不看静默、门/尾门。
- 必要性：静默期（连续 3 次安全失败锁定）仍可能自动解闭锁；门/尾门开着时断连闭锁可能夹人/夹物。
- 不修改风险：不改则静默期仍动作、门/尾门开仍可能断连闭锁。
- 实际改动：
  - 新增 `phone_sm_is_silent()` / `phone_comm_is_silent()` 访问器；
  - 尾门 `BackDoorSt` 并入 `door_status` 第 5 位（`0x10`）；
  - 自动解锁加静默拦截；
  - 断连闭锁启动加“非静默 + 门/尾门全关”，取消加“静默开始或门/尾门打开”。
- 文件与函数：`user_phone/data/phone_sm.c/.h`、`user_phone/phone_comm.c/.h`（静默访问器）；`user_app_fun/user_app_fun.c`（尾门并入 door_status）；`user_app_fun/user_app_phone_peps.c` 的 `user_app_phone_peps_process()`（门控）。
- 影响范围：只影响 PEPS 自动解锁/断连闭锁门控；不改 CR008 授权语义、冻结接口和串口。
- 与 CR008 和 CR009 其他子项的冲突检查：不改 CR008-009 授权门控；收紧 CR008-010 断连闭锁条件（需回归）；与 CR009-006 同段代码，006 已先提交；与 CR009-002/003 不冲突。
- 编译方法：Simplicity Studio 编译，仅改 `.c/.h`。
- 前后对比实测方法：静默期不自动解锁/闭锁；门/尾门开不闭锁；全关+断连 5s 正常闭锁；计时中开门取消；回归 CR008-009/010、CR009-006。
- 实际验证证据：用户确认编译通过，实机待测。
- 提交：待提交。
