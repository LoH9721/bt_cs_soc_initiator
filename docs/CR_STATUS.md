# CR 开发进度总览

更新时间：2026-08-19

本文件是所有 CR 的唯一实时进度入口。各 CR 的 PLAN 负责范围、方案和验证设计；CHANGE_RECORD 负责已经实施的实际改动；`PROJECT_HANDOFF.md` 只保留阶段交接快照和继续点。

## 1. 管理规则

- 顶层变更使用 `CR008`、`CR009`；子项必须完整写成 `CR008-009`、`CR009-001`，不得把 `CR008-009` 简写为 `CR009`。
- 子项编号一旦分配便不删除、不重排、不复用；不再实施时标记 `CANCELLED` 并记录原因。
- 新发现的问题先进入 `ISSUE_LOG.md`，评审后再决定：并入当前子项、新增当前 CR 子项、升级为新 CR，或关闭。
- 已经 `CODED` 及之后的子项不得静默改范围；范围发生实质变化时新增子项，并记录依赖或替代关系。
- 同一时间最多一个子项进入代码实施状态 `IN_PROGRESS`；验证和补测可以跨 CR 并行。
- 代码、编译、实机验证分别记录；部分实测不直接标记 `TESTED`。

状态定义：

| 状态 | 含义 |
|---|---|
| CANDIDATE | 候选方向，尚未确认纳入 |
| TODO | 已确认纳入，尚未开始 |
| IN_PROGRESS | 当前正在设计或实施 |
| CODED | 代码完成，尚未确认编译通过 |
| BUILT | 用户确认编译通过，实机验证未完成 |
| TESTED | 计划内单项与回归实测完成 |
| ACCEPTED | 用户确认验收/收口 |
| BLOCKED | 存在明确阻塞 |
| CANCELLED | 评审后取消；编号永久保留 |
