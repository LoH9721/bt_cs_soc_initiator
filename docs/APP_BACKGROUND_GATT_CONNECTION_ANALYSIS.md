# APP 后台 HID 连接与 GATT 重连分析

## 1. 文档目的

记录 Android 系统已经通过 HID 在后台连接 BG24 时，手机 APP 无法立即建立业务 GATT 会话的现象、日志证据、根因和 APP 侧推荐策略。

本文只分析连接发现与复用策略，不修改 APP-BG24 业务协议，不修改 HID、Pairing/Bonding、自动重连和无感解闭锁逻辑。

## 2. 结论

当前问题不是 BG24 连接数量不足，也不是业务认证失败，而是：

1. Android 系统先通过 HID 建立了物理 BLE 连接；
2. BG24 在首个手机连接建立后停止可连接广播；
3. APP 在没有缓存设备地址时只执行扫描，扫描不到已经停止广播的 BG24；
4. APP 获得并缓存 BG24 的稳定地址后，可以直接连接 GATT，并复用 Android 已存在的物理连接；
5. 因此，APP 应采用“稳定地址直连优先、扫描兜底”，不能把扫描作为唯一入口。

## 3. 日志证据

### 3.1 APP 无地址时只能扫描并连续超时

日志：`CAKY_LOG_20260817210153.txt`

- 第 34 行：开始扫描 APP GATT 广播；
- 第 527 行：扫描 10 秒超时；
- 第 538 行：再次开始扫描；
- 第 1036 行：再次扫描超时。

### 3.2 BG24 已被 Android 系统后台连接并停止广播

日志：`新建文本文档 (3).txt`

- 第 37～44 行：连接 9 建立，Bond 有效，安全等级由 L1 升至 L4；
- 第 39 行：`Advertising stopped (connected)`；
- 此时 APP 依赖扫描，无法发现 BG24，行为与 APP 扫描超时一致。

### 3.3 广播恢复后 APP 扫描成功

APP 日志第 1050 行重新开始扫描，随后发现设备、建立连接并在第 1104～1119 行完成业务互认证。

这说明 APP 自定义 GATT 服务和业务认证链路本身正常。

### 3.4 缓存地址后可以直接复用现有连接

APP 日志：

- 第 1142～1143 行：APP 进入后台，主动释放自身 GATT 客户端；
- 第 1152 行：发现缓存地址 `90:39:5E:C4:E3:C8`，优先 APP GATT 直连；
- 第 1175～1190 行：再次完成业务互认证。

BG24 日志：

- 第 352 行：APP 释放通知，`TX CCCD DISABLED`；
- 第 353 行：APP 恢复后重新订阅，`TX CCCD ENABLED`；
- 第 393～485 行：在没有新的 `connection_opened` 事件的情况下再次完成业务认证。

这表明 Android 可以让 APP 复用系统已经持有的 BLE 物理连接；关键条件是 APP 知道目标设备地址并执行直连。

## 4. APP 推荐连接策略

建议 APP 持久化：

`vehicleId/deviceId -> BG24 稳定 Identity Address`

连接优先级：

1. APP 本地存在已绑定车辆地址：直接调用 GATT 连接；
2. APP 本地无地址，但 Android 系统 Bond 列表中能找到目标设备：恢复地址后直连；
3. 前两项均不可用，或者直连明确失败：再启动扫描；
4. 扫描发现并完成设备身份校验后，更新本地地址缓存；
5. 不能仅因扫描不到设备就判定车辆离线，应区分“设备未广播”和“设备不可连接”。

推荐状态流：

```text
取得目标车辆
  -> 有 APP 地址缓存？是 -> GATT 直连
  -> 否：系统 Bond 中可恢复地址？是 -> GATT 直连
  -> 否 -> 扫描发现
  -> 服务发现 + 通知订阅
  -> 读取 deviceId 并校验
  -> 业务互认证
  -> 连接可用
```

## 5. 暂不建议的固件改法

不建议仅为解决 APP 扫描问题，就让 BG24 在已有手机连接时继续接受第二个手机物理连接。当前固件的连接句柄、业务会话、HID 状态和测距状态主要按单手机使用设计；直接开放第二个物理连接可能导致当前连接状态被覆盖。

在“只有一把手机钥匙”的当前产品约束下，APP 使用稳定地址直连并复用 Android 连接，改动更小、边界更清晰。

## 6. 验证用例

1. Android 已完成系统 Bond，APP 清除运行内存但保留地址缓存：系统后台连接后打开 APP，应不扫描或仅短暂等待，直接进入 GATT 服务发现和业务认证。
2. APP 进入后台再回前台：BG24 不出现新的 `connection_opened` 也允许；应看到 CCCD 重新使能和业务认证成功。
3. APP 地址缓存丢失但系统 Bond 仍在：APP 应从系统 Bond 列表恢复地址并直连。
4. APP 和系统均没有地址信息：APP 才走扫描发现流程。
5. 缓存地址失效或设备身份校验失败：清理错误映射并回退扫描，不能连接错误车辆。

## 7. 与重新配对问题的边界

Android 删除系统 Bond 后，APP 是否允许重新配对属于 Pairing/Bonding 状态一致性问题，与本文的“后台连接时扫描不到设备”是两个独立问题。

APP 应分别维护：

- 业务绑定状态：APP 与车辆业务身份是否仍有效；
- Android Bond 状态：系统是否仍持有 BLE Bond；
- 无感功能配置状态：BG24 的 `passiveEnabled` 是否开启。

三者不能互相替代。尤其不能用 `passiveEnabled=true` 推断 Android Bond 仍然存在。
